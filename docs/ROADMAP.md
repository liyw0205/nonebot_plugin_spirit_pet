# 开发路线

README 仅介绍仓库；这里记录实施顺序与验收口径，不把计划描述成已实现功能。

## 当前阶段：可运行的开发版

已实现：

- 双适配器共用 SQLite，身份严格使用原始 ID，无绑定或推测映射。
- 独立目录职责、严格静态 JSON、事务内 Repository、幂等和失败回滚。
- 27 种灵宠，固定四种初选，召唤与秘境灵卵孵化、出战切换、七境十层、五阶血脉、道具、奇遇、每日任务。
- 随机唯一道号与道号交互、八类种族、主副属性、五行分支与特殊元素、十类天赋效果。
- 三装备位与 +0 至 +10 强化、强化卸装保留、秘笈学习与携带、五级技能熟练度成长、复合元素门槛与属性克制。
- 单人 PVE、直接挑战镜像的排行榜 PVP、按道号无损切磋、全员准备的组队秘境。
- Linux/Windows/Termux 安装与 OneBot 反向 WS、QQ 官方接入文档。
- 自动化测试与不依赖 NapCat 的真实 ASGI/WS 冒烟测试。

开发期允许重构，不背负旧内部接口兼容；任何存档格式变化必须明确拒绝不支持的旧库，不能自动销毁数据。

## 已完成阶段：内容与数值

1. 27 个种族各两条血脉分支，共 54 条。选定后有实际四维成长取舍，存档独立、成本原子扣除，不丢元素或装备技能。
2. 主动控制、弱化、护盾、增益、净化、驱散六类效果，六种对应灵术。行动次数与互斥/刷新规则直接测试，含快慢手、双敌轮控、施放熟练度和真实 PVE/PVP 结算。
3. 全部 14 件装备可打造和分解；只消耗指定等级的背包装备，回收部分材料、不退灵石，静态检查覆盖全强化等级的材料损耗与采购套利。
4. 补齐七境共 16 个单人/组队秘境。固定种子完成基础 626 个场景、62,600 场仿真，覆盖单人、双人、三人和单位时间收益；另以 120 个专项场景、12,000 场战斗验证 54 条分支与六类主动效果真实生效，保留失败和平局结果。详细范围与局限见 [数值验收](BALANCE.md)。

分支是种族内的成长路线，不是物种转换。当前资源秘境强调成长后稳定取材；仿真基线不代表完成全部竞技配装平衡。

## 当前阶段：社交与长期目标

1. 已完成队伍申请审批、邀请确认、按权限分页队务、踢人、转让和显式解散；按道号交互，成员变化清全队准备。测试覆盖最后名额竞态、跨队同时批准、到期边界、重启、改名、重投和出征/离队并发，真实 WS 验证授权与管理流程。
2. 已完成三类离线委托：开始、查询、到期归来与提前召回。每人一项、原宠占用、运行奖励快照和永久出发消息键；无参只查询，旧行程不能操作新行程。测试覆盖全部占用入口、期限边界、重启、内容变更、七天后重投与领取/召回/战斗并发，真实 WS 和双适配器事件模型验证命令流程。
3. 已实现自然月独立赛季、冻结规则/奖励、同境界积分区间候选与榜单直接镜像挑战、主动日总额和同对日/季额度、有效对手资格及结束后一次领奖。不再使用邀请/应战流程；仅挑战者消耗资源或增长熟练度，防守只影响积分战绩。永久保存论剑来源凭证和回复，覆盖跨月、时钟回退、限额/领奖并发、失败回滚、长期重投及 QQ 富消息和真实 WS 命令。防刷仅限原始 ID 的次数/收益约束，不声称能杜绝串谋。
4. 已完成线性单人/组队关卡与永久战报。八个关卡使用静态定义与独立进度，组队逐人校验前置关卡和准备状态；首通奖励每人每关一次，已通关者可助战。失败不推进但照常消耗精力、冷却并记录真实技能施放。论剑、切磋、单人/组队秘境与关卡均保存战前阵容快照和完整战斗事件；参与者按原始 ID 授权查看，消息缓存过期后仍永久幂等重放。
5. 已完成成就与收集：静态定义覆盖宠物数量/种类、成长、关卡、论剑/PVE、分支和灵术；进度从 SQLite 当前存档与永久战绩派生，图鉴分页展示种族拥有情况。领取写入永久唯一凭证、奖励快照和回复，并与资源变更处于同一事务；覆盖并发、失败回滚和七天缓存过期后的重投。
6. 当前迭代本地验收：全量测试 `1278 passed, 1 skipped`，`compileall` 与差异检查通过；双适配器原始 ID 隔离测试、真实 ASGI/OneBot WS 冒烟覆盖关卡、战报、成就与收集入口，Linux 隔离安装后的 WS 冒烟和 `xiupet` 安装/启停链路也通过。静态 JSON 仅含定义，玩家身份、进度、时间和奖励领取均在 SQLite。远端最近成功 run 是 `5ed9d19` 的 workflow_dispatch，6 个 Linux/Windows、Python 3.10/3.13 测试与安装 job 通过；当前推送提交尚无远端 run。Termux 和 QQ 真机仍未验收。

推进顺序固定为队伍审批与管理 → 离线任务 → 赛季匹配及防刷 → 战斗记录与关卡 → 成就收集，均已有中文入口、状态展示、事务/重投测试和文档。

## 稳定发布前

1. 待用真实 QQ AppID 与客户端验收普通消息、Markdown、键盘、蓝字及权限降级；自动化事件测试不能替代平台权限和真机呈现确认。
2. GitHub Actions 用 Linux/Windows、Python 3.10/3.13 回归游戏与适配器，并在隔离目录验证一键安装、`xiupet` 管理命令和 WS 冒烟；Linux 缺 Python 的包管理器自举路径另由隔离 shell 测试验证。工作流只负责质量门禁。
3. 首个公开版本候选冻结 schema 11：接受全新空库与 schema 11，拒绝 schema 1-10、未来版本及未版本化非空库且不修改原文件；不迁移未发布开发库，旧库备份保留并给新版本配置新路径。未来若要携带已发布存档升级，须先提供独立迁移和回滚验证。SQLite Online Backup API 的备份/验证/非覆盖恢复工具已用完整 schema 11 临时库演练，包含已存在目标保护。
4. GitHub 一键脚本从校验过的源码归档安装完整机器人项目，生成 `xiupet` 管理命令并使用 `nb run` 启动，不依赖外部插件包索引。
5. 默认发布路径为 GitHub 源码与 Linux/Windows/Termux 安装入口。完成远端 CI、Termux 与 QQ 验收后再冻结版本、创建正式标签并发布说明；发行说明需明确 Python 支持范围、schema 11 的拒绝旧库策略、双适配器原始 ID 边界及 QQ/Termux 的实测限制。
