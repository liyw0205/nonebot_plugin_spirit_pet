2. 已完成三类离线委托：开始、查询、到期归来与提前召回。每人一项、原宠占用、运行奖励快照和永久出发消息键；无参只查询，旧行程不能操作新行程。测试覆盖全部占用入口、期限边界、重启、内容变更、七天后重投与领取/召回/战斗并发，真实 WS 和双适配器事件模型验证命令流程。
3. 已实现自然月独立赛季、冻结规则/奖励、同境界积分区间候选与榜单直接镜像挑战、主动日总额和同对日/季额度、有效对手资格及结束后一次领奖。不再使用邀请/应战流程；仅挑战者消耗资源或增长熟练度，防守只影响积分战绩。永久保存论剑来源凭证和回复，覆盖跨月、时钟回退、限额/领奖并发、失败回滚、长期重投及 QQ 富消息和真实 WS 命令。防刷仅限原始 ID 的次数/收益约束，不声称能杜绝串谋。
4. 已完成线性单人/组队关卡与永久战报。八个关卡使用静态定义与独立进度，组队逐人校验前置关卡和准备状态；首通奖励每人每关一次，已通关者可助战。失败不推进但照常消耗精力、冷却并记录真实技能施放。论剑、切磋、单人/组队秘境与关卡均保存战前阵容快照和完整战斗事件；参与者按原始 ID 授权查看，消息缓存过期后仍永久幂等重放。
5. 已完成成就与收集：静态定义覆盖宠物数量/种类、重复种族、成长、亲密、连续陪伴、关卡、论剑/PVE、组队 PVE、分支、灵术和委托归来；组队 PVE 成就按战报中的多人同侧胜场统计，1/10/30 场分别提供长期里程碑。进度从 SQLite 当前存档与永久战绩/已领取行程派生，图鉴分页展示种族拥有数量与重复种族数。领取写入永久唯一凭证、奖励快照和回复，并与资源变更处于同一事务；覆盖并发、失败回滚和七天缓存过期后的重投。
6. 已完成灵宠共鸣：14 种双种族组合覆盖全部种族；每人单独启用一种，启用成本原子扣除，切换时重置本人队伍准备。加成只作用于组合内种族的当前出战宠物，并写入战斗快照；测试覆盖种族隔离、并发扣费、状态展示和战斗数值。
7. 上一轮记录的本地验收：全量测试 `1379 passed`；`compileall`、真实 ASGI/OneBot WS 冒烟，以及基础 62,600 场与专项 12,400 场固定种子仿真通过。这是已有范围的历史证据，当前 D1-D3 按最终状态另行核对；原矩阵尚未覆盖本轮三宠/五宠阵容。测试也覆盖 Linux 安装器缺少 Python 时的包管理器自举、隔离安装、`xiupet` 启停/状态和卸载。Termux 安装尚未在设备上实测。静态 JSON 仅含定义，玩家身份、进度、时间和奖励领取均在 SQLite。

推进顺序为队伍审批与管理 → 离线任务 → 赛季匹配及防刷 → 战斗记录与关卡 → 成就收集 → 灵宠共鸣 → 多宠出战阵容与战斗结算；均已有中文入口、状态展示、事务/重投测试和文档。

## 外部验收与正式发布

状态：QQ 真机呈现与权限、Termux 真机安装分别为独立待验项；正式 Release `v0.1.0` 已发布。环境到位后执行对应验收，不因等待而重复已通过的本地测试。

1. QQ 待用真实 AppID 与客户端验收普通消息、Markdown、键盘、蓝字及权限降级，记录账号权限、客户端和实际结果；自动化事件测试不能替代平台权限和真机呈现确认。
2. Termux 待在设备上验收安装、更新、启停、卸载及存档保护，记录设备环境和实际结果。Linux 缺少 Python 的自举模拟、安装/卸载隔离、`xiupet` 进程管理与 WS 冒烟已有本地测试，按开发指南在相关变更或交付阶段核对即可。
3. 当前开发 schema 为 20：接受全新空库，已按用户保留存档要求交付完整 schema 18 / 19 的备份迁移；拒绝 schema 1-17、未来版本及未版本化非空库，不重建或清空原文件。备份/回滚与 UID/注册时间边界见 [开发指南](DEVELOPMENT.md#添加一个玩法)。本轮合修不变更 schema，也不重跑已交付迁移验证。
4. Bash 一键脚本从校验过的源码归档安装完整机器人项目，生成原生 shell `xiupet` 管理命令并使用 `nb run` 启动；Python 只用于建立环境和安装运行依赖，不承担安装器、进程管理器或卸载逻辑。
5. 默认发布路径为 GitHub 源码与 Linux/Termux 安装入口；用户文档始终面向 `main` 和正式 Release。发行说明需明确 Python 支持范围、schema 20 的保留迁移/拒绝范围、双适配器原始 ID 边界及 QQ/Termux 的实测限制。
