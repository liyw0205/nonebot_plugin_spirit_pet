# 开发路线

README 仅介绍仓库；这里记录实施顺序与验收口径，不把计划描述成已实现功能。

## 当前阶段：可运行的开发版

已实现：

- 双适配器共用 SQLite，身份严格使用原始 ID，无绑定或推测映射。
- 独立目录职责、严格静态 JSON、事务内 Repository、幂等和失败回滚。
- 27 种灵宠，固定四种初选，召唤与秘境灵卵孵化、出战切换、七境十层、五阶血脉、道具、奇遇、每日任务。
- 随机唯一道号与道号交互、八类种族、主副属性、五行分支与特殊元素、十类天赋效果。
- 三装备位与 +0 至 +10 强化、强化卸装保留、秘笈学习与携带、五级技能熟练度成长、复合元素门槛与属性克制。
- 单人 PVE、双方确认的积分 PVP、无损切磋、全员准备的组队秘境。
- Linux/Windows/Termux 安装与 OneBot 反向 WS、QQ 官方接入文档。
- 自动化测试与不依赖 NapCat 的真实 ASGI/WS 冒烟测试。

开发期允许重构，不背负旧内部接口兼容；任何存档格式变化必须明确拒绝不支持的旧库，不能自动销毁数据。

## 下一阶段：内容与数值

1. 扩充种族专属血脉分支、主动技能控制与驱散规则，在已有天赋、护盾和毒伤之上扩展效果模型。
2. 在已有强化基础上加入打造和分解，设计材料来源/消耗/上限，禁止只加资源不加回收。
3. 用固定随机种子批量模拟各阶段单人、双人和三人战斗，记录胜率与单位时间收益。
4. 验收：效果互斥与叠加规则可测试；常见阵容无必败或无限循环；所有掉落引用可静态校验。

这一节所列的后续内容尚未实现；已有天赋、强化、熟练度、装备、主动技能与元素克制不属于待办。现有血脉仍是通用等级倍率，不是物种转换或技能树。

## 后续阶段：社交与长期目标

1. 队伍邀请审批、成员管理与离线任务，保持成员授权和资源事务边界。
2. 赛季、匹配区间与防刷策略；当前同对玩家每日一次积分结算不等于完整反滥用系统。
3. 副本关卡与战斗记录、成就和收集目标，给长期内容设置明确进度与奖励上限。
4. 验收：跨日/赛季边界、重启、失败重试、重复消息和成员中途离队都不重复发奖。

## 稳定发布前

1. 在真实 QQ AppID 与客户端验收普通消息、Markdown、键盘、蓝字及权限降级。
2. 跑完整 Linux/Windows CI 和 Termux 回归，并验证全新安装路径。
3. 冻结正式存档结构之后，再制定版本迁移、备份恢复与回滚契约。
4. 单独设计 PyPI 构建元数据并验证 JSON/SQL 包含，不把当前 NoneBot 项目 TOML 当成已经可发布的 Python 分发包。
5. 发布标签、变更说明、许可证和 NoneBot 插件索引资料，明确支持范围与已知限制。
